Спеціальність: F2 «Інженерія програмного забезпечення»
1. Назва проєкту


• Українською: Підсистема динамічного планування та оптимізації багатофазних процесів в умовах гетерогенних ресурсних обмежень

• Англійською: Dynamic Multi-Phase Scheduling and Resource Optimization Subsystem under Heterogeneous Constraints

2. Актуальність та проблематика
Традиційні підходи до диспетчеризації ресурсів у сервісних інформаційних системах спираються на дискретну модель фіксованих квантів часу («один неподільний слот — один виконавець — одна операція»). 
При плануванні складних технологічних ланцюжків, що містять гетерогенні етапи (активні фази за участю фахівця та пасивні фази технологічного очікування клієнта), класичні моделі спричиняють простої інфраструктури (до 30–45%) та знижують загальну пропускну здатність системи.
Інженерна та алгоритмічна складність задачі зумовлена такими факторами:

• Обчислювальна складність: Задача належить до класу NP-важких варіацій RCPSP (Resource-Constrained Project Scheduling Problem) із неперервною темпоральною шкалою.

• Багатовимірні топологічні обмеження: Об'єкт обслуговування одночасно є споживачем послуги та просторовим контейнером суб-ресурсів одиничної місткості, що вимагає динамічної верифікації сумісності без використання статичних матриць виключення.

• Вимоги до реактивності та транзакційності: Необхідність субрекурентного (sub-second) формування розкладу за лексикографічним вектором критеріїв в умовах інтенсивного паралельного доступу без виникнення станів гонитви (race conditions) та фантомних бронювань.

3. Об'єкт, предмет та мета розробки

• Об’єкт дослідження: Процеси темпорального та просторового планування складних взаємопов'язаних операцій у розподілених сервісних системах.

• Предмет дослідження: Алгоритми задоволення обмежень (Constraint Satisfaction), структури даних інтервальної логіки, архітектурні патерни ізоляції CPU-інтенсивних обчислень та транзакційні механізми конкурентного контролю в реляційних СУБД.

• Мета проєкту: Проєктування та інженерна реалізація високопродуктивної програмної підсистеми оптимізаційного планування багатофазних процесів, здатної функціонувати як автономне обчислювальне ядро для інтеграції в enterprise-системи управління ресурсами.

4. Архітектура та функціональні складові (Core Features)
    1. Декларативне моделювання багатофазних процесів (Process Decomposition Engine):
    ◦ Формалізація складених послуг у вигляді ациклічних графів залежностей між активними фазами (блокування виконавця) та технологічними інтервалами (вивільнення персоналу для паралельного обслуговування інших вузлів).
    2. Ядро оптимізації на основі програмування в обмеженнях (CP-SAT Core):
    ◦ Побудова розкладу з використанням розв'язувача Google OR-Tools (інтервальні змінні NewOptionalIntervalVar, констрейнти AddNoOverlap).
    ◦ Реалізація лексикографічної оптимізації: мінімізація сумарного вікна перебування $\to$ мінімізація дискретної ротації персоналу $\to$ мінімізація дельти від цільового часу запиту.
    ◦ Механізм асинхронного тайм-ауту (time-budgeting) із поверненням квазіоптимального плану.
    3. Базовий інтервальний аналізатор (Heuristic Baseline Solver):
    ◦ Реалізація евристичного алгоритму на базі інтервальних дерев для порівняльного аналізу сходимості, пам'яттєвої складності та часу виконання проти декларативної CP-SAT моделі.
    4. Транзакційний конкурентний контроль на рівні СУБД (Range-Level Concurrency Control):
    ◦ Запобігання колізіям за допомогою темпоральних діапазонів tstzrange та обмежень взаємного виключення EXCLUDE USING gist у PostgreSQL, що усуває race conditions на рівні ACID-транзакцій без використання розподілених блокувань.
    5. Реактивна синхронізація станів (Reactive State Distribution):
    ◦ Двоетапне бронювання: тимчасове холдування ресурсу (Hold Lifecycle) з автоматичним TTL-вивільненням через асинхронні черги задач.
    ◦ Трансляція мутацій розкладу клієнтам у режимі реального часу за допомогою Server-Sent Events (SSE) та шини подій на базі Redis Pub/Sub із дотриманням патерну Transactional Outbox.
    6. Диспетчерський інтерфейс взаємодії (Interactive Dispatcher Timeline):
    ◦ Багатодоріжковий інтерфейс диспетчеризації з динамічною візуалізацією паралельних підфаз та підтримкою інтерактивної корекції розкладу з автоматичним валідуванням залежностей.

5. Технологічний стек та інженерна інфраструктура
• Мови програмування: Python 3.12+ (Backend, Обчислювальне ядро), JS/TypeScript (Frontend).

• Архітектура: Domain-Driven Design (DDD), Clean Architecture, Event-Driven Architecture, Task-Worker Pattern.

• Бекенд та обчислення:

    ◦ Web API: FastAPI, Pydantic v2.

    ◦ Solvers & Data Structures: Google OR-Tools (CP-SAT), portion, intervaltree.

    ◦ Асинхронне виконання та черги: asyncio, taskiq, Redis.

• Бази даних та персистентність:

    ◦ СУБД: PostgreSQL 16+ (btree_gist, темпоральні діапазони).

    ◦ ORM / Міграції: SQLAlchemy 2.0 (AsyncIO / asyncpg), Alembic.

• Фронтенд:

    ◦ Фреймворк: Vue.js 3 (Composition API), Vite, Pinia.

    ◦ Синхронізація стану: @tanstack/vue-query, @hey-api/openapi-ts (контрактна генерація клієнта за OpenAPI-специфікацією).

• Контроль якості, тестування та CI/CD:

    ◦ Тестування інваріантів алгоритмів: Hypothesis (Property-based testing коректності обмежень).

    ◦ Інтеграційне тестування: pytest, pytest-asyncio, testcontainers-python (ізольовані екземпляри PostgreSQL та Redis у Docker).

    ◦ Навантажувальне тестування: k6 (валідація пропускної здатності та поведінки при станах гонитви).

    ◦ Статичний аналіз та інструменти коду: Ruff, mypy (strict mode), pre-commit.

    ◦ Інфраструктура: Docker, Docker Compose, GitHub Actions CI.
